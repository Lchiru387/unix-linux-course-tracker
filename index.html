What is an operating system?

An operating system (OS) is the software layer that manages computer hardware and provides services to applications. In Linux, the kernel is the core component: it manages CPU scheduling, memory, devices, filesystems, networking, processes and system calls. A Linux distribution packages the kernel with user-space programs, libraries, package management, configuration and administration tools.

Linux system — the big picture

Layer / resourceWhat it doesWhat to check
CPUExecutes instructions. Processes/threads compete for CPU time and are scheduled by the kernel.lscpu, top, ps
RAM / memoryFast working memory used by applications and the kernel. Linux also uses memory for page cache and can use swap when appropriate.free -h, vmstat
Disk / storagePersistent storage for files, applications, logs, databases and the OS. Much slower than RAM.df -h, du -sh
FilesystemOrganizes persistent data into files/directories and tracks metadata such as ownership and permissions.ls -l, df -T, findmnt
ProcessesRunning instances of programs. Each process has a PID and consumes resources.ps aux, pgrep
NetworkProvides communication between the host and other systems/services.ip addr, ss -tulnp
KernelControls access to hardware and provides system calls used by user-space programs.uname -a, uname -r
ShellCommand interpreter such as Bash; handles variables, expansion, pipelines, redirection and command execution.echo "$SHELL", echo "$PATH"

CPU vs memory vs disk — understand the difference

CPU is compute capacity, RAM is working space, and disk is persistent storage. A program normally lives on disk, is loaded into memory, and its instructions are executed by the CPU. The kernel coordinates this movement and resource usage.

SymptomLikely areaFirst checks
CPU near 100% for a long timeCPU / busy processestop, ps aux --sort=-%cpu
Very little available memory, heavy swappingRAM / memory pressurefree -h, vmstat 1, swapon --show
Filesystem at 90–100%Disk capacity / filesystemdf -h, then du -xhd1 /path
High I/O wait / slow disk operationsStorage I/Otop, vmstat 1, iostat if installed
Application cannot connect to a serviceNetwork / servicess -tulnp, systemctl status ..., logs

Memory concepts you should know

  • Used memory is not simply “application memory”. Linux uses RAM for processes, the kernel and filesystem page cache.
  • Available memory is generally more useful than looking only at the “free” column when judging whether the system is under memory pressure.
  • Virtual memory gives processes virtual address spaces; the kernel maps those addresses to physical memory pages and may reclaim or swap eligible pages.
  • Swap is disk-backed space used by the memory-management system. Heavy swap activity can be a sign of memory pressure and is much slower than RAM.
free -h
vmstat 1
swapon --show
cat /proc/meminfo | head -n 15

CPU and load average

CPU utilization tells you how busy the processors are. Load average is different: it reflects the average number of tasks that are runnable or waiting in uninterruptible states. Always interpret load in relation to the number of CPU cores.

lscpu
uptime
top
ps -eo pid,ppid,comm,%cpu,%mem --sort=-%cpu | head

Processes and system calls

Applications normally run in user space. When they need privileged kernel services—such as opening a file, creating a process, allocating resources or communicating with a device—they use system calls. The kernel performs the operation subject to permissions and system rules.

ps aux
pgrep -a java
cat /proc/$$/status | head
uname -r

Filesystem hierarchy

Know the purpose of common directories such as /etc (system configuration), /var (variable data/logs), /home (user home directories), /tmp (temporary files), /usr (most user-space programs and data), /dev (device files), /proc (kernel/process information exposed as a virtual filesystem), and /run (volatile runtime data).

Important first commands

uname -a
cat /etc/os-release
whoami
id
pwd
echo "$SHELL"
echo "$PATH"
free -h
df -h
uptime
ps aux
man ls
command -v ls

Operational mindset: when a server is slow, do not immediately assume “CPU problem.” Check CPU, memory/swap, disk capacity, disk I/O, processes, network and service logs, then correlate the evidence.

Absolute vs relative paths

Absolute path — always starts with / (root), works the same from anywhere. Example: /var/log/syslog can be read with cat /var/log/syslog from any directory.

Relative path — starts from your current working directory (PWD), never begins with /. Uses . for current dir and .. for parent. Example: from /var, the relative path to syslog is log/syslog; from /var/log, cd ../tmp goes up to /var then into tmp.

Permissions

Every regular file has permissions for user (u), group (g), and other (o). The basic bits are read, write and execute. For directories, execute means the ability to traverse/search the directory.

CommandPurposeExample
ls -lInspect mode, owner and groupls -l app.conf
chmodChange permission bitschmod 640 app.conf

Numeric permissions

755 = rwxr-xr-x; 644 = rw-r--r--; 640 = rw-r-----. Avoid giving execute/write permission unless it is actually required.

Sudo and ACLs

Use least privilege: grant the minimum access needed, and remember that ACLs can provide permissions beyond the basic owner/group/other mode bits.

pgrep -f vs pgrep -x

pgrep -f "java" matches against the entire command line, not just the process name — so java -jar myapp.jar and /usr/bin/python script_using_java.py would both match. That can cause false positives if unrelated commands happen to contain "java" in their arguments.

Check a process is running, restart if not

#!/bin/bash
PROCESS_NAME="java"
START_COMMAND="/path/to/start.sh"
WAIT_SECONDS=5
LOG_FILE="/var/log/java_monitor.log"

# Check if Java process is running
if ! pgrep -f "$PROCESS_NAME" > /dev/null; then
  echo "Process not running. Waiting $WAIT_SECONDS seconds..."
  sleep $WAIT_SECONDS
  echo "Starting process..."
  $START_COMMAND &
  echo "$(date): Java process restarted" >> "$LOG_FILE"
else
  echo "Process is already running."
fi

! negates the result: pgrep exits 0 (true) if it finds a match and 1 (false) if it doesn't — ! flips that, so the block only runs when the process is not running.

What is systemd?

systemd is the system and service manager used by many modern Linux distributions. It manages units such as services, sockets, mounts, timers and targets. A .service unit describes a process supervised by systemd.

Most-used systemctl commands

CommandPurpose
systemctl status nginxShow service state and recent status information
systemctl start nginxStart a service now
systemctl stop nginxStop a service now
systemctl restart nginxStop and start the service
systemctl reload nginxAsk the service to reload configuration without a full restart, when supported
systemctl enable nginxConfigure the service to start automatically at boot
systemctl disable nginxRemove its boot-time enablement
systemctl is-active nginxCheck whether it is currently active
systemctl is-enabled nginxCheck whether it is enabled for startup
systemctl --failedList failed units

Unit files

A service unit commonly contains [Unit], [Service], and [Install] sections. Important settings include Description=, After=/Requires=, ExecStart=, User=, Restart= and WantedBy=.

[Unit]
Description=My Application
After=network.target

[Service]
User=appuser
ExecStart=/opt/myapp/start.sh
Restart=on-failure

[Install]
WantedBy=multi-user.target

Changing a unit safely

systemctl edit myapp.service
systemctl daemon-reload
systemctl restart myapp.service
systemctl status myapp.service

Important: daemon-reload reloads unit configuration; it does not by itself restart the service.

Common troubleshooting flow

systemctl status myapp.service
journalctl -u myapp.service -n 100
journalctl -u myapp.service --since "30 minutes ago"
systemctl list-dependencies myapp.service

6 concepts

df — filesystem-level capacity

df reports the space used and available on mounted filesystems. Think of df as the filesystem / partition view, not the “which directory contains my files?” view.

df -h
df -h /var
df -T
df -i
df -x tmpfs -h
CommandWhat it tells you
df -hFilesystem size, used space, available space, percentage used and mount point in human-readable units.
df -TAlso shows filesystem type, such as ext4, xfs, btrfs or another supported type.
df -iShows inode usage. A filesystem can run out of inodes even when it still has free bytes.
df -h /pathShows the filesystem that contains the supplied path.

Reading df -h

Filesystem      Size  Used Avail Use% Mounted on
/dev/sda2        80G   68G   12G  85% /
/dev/sdb1       500G  220G  280G  45% /data

Size = filesystem capacity, Used = space currently accounted as used, Avail = space available to users/filesystem operations, Use% = percentage used, and Mounted on = where that filesystem appears in the directory tree.

du — directory/file-level usage

du estimates the space used by a set of files. Think of du as the directory / file investigation view. It is the command you normally use after df tells you a filesystem is filling up.

du -sh /var/log
du -sh /var/log/*
du -h --max-depth=1 /var
du -xhd1 /var
du -ah /var/log | sort -hr | head -n 20
OptionMeaningExample
-hHuman-readable sizesdu -h /var
-sSummary instead of listing every descendantdu -sh /var/log
-aInclude files as well as directoriesdu -ah /var/log
--max-depth=1Show one directory level below the targetdu -h --max-depth=1 /var
-xStay on the same filesystem; do not cross into mounted filesystemsdu -xhd1 /

df vs du — the most important distinction

QuestionUseExample
How full is the filesystem?dfdf -h /
Which directory is consuming space?dudu -xhd1 / | sort -h
Which files are largest?du + find/sortfind /var -type f -exec du -h {} + | sort -hr | head
Are inodes exhausted?df -idf -ih

Why can df and du show different numbers?

  • Deleted but still-open files: a process can keep a deleted file open, so du may not find the pathname while the filesystem space remains allocated. Use lsof +L1 to investigate on systems where lsof is installed.
  • Different filesystem boundaries: du /path can traverse into mounted filesystems. du -x keeps the investigation on one filesystem.
  • Filesystem metadata / reserved space / implementation details: df reports filesystem-level accounting, while du estimates usage from the files it examines. They are answering related but different questions.
  • Special filesystems and mounts: systems can contain virtual or network filesystems that do not behave like ordinary local storage.

Practical disk-space troubleshooting

# 1. Identify the full filesystem
df -h

# 2. Identify the filesystem type and inode usage
df -T
df -i

# 3. Find the largest top-level directories on that filesystem
du -xhd1 / | sort -h

# 4. Drill into the suspicious directory
du -xhd1 /var | sort -h

# 5. Find large files
find /var -xdev -type f -size +500M -ls

# 6. Check deleted files still held open by processes
lsof +L1

Common operational checks

ProblemChecks
“Disk is full”df -h → du -xhd1 → drill down to large directories/files.
“No space left” but df -h looks okayCheck df -i for inode exhaustion and investigate application-specific limits.
du total seems smaller than dfCheck mount boundaries, deleted-open files, filesystem accounting and special filesystems.
Log directory is growingUse du -sh /var/log/*, inspect log rotation, and check whether an application is producing excessive logs.

Remember: df answers “How full is the filesystem?”; du answers “Which files/directories are consuming space?”. In production troubleshooting, start with df, then use du to locate the cause.

Hard links vs symbolic links

FeatureHard linkSymbolic (soft) link
Creationln file linkln -s target link
What it storesAnother directory entry for the same inodeA pathname pointing to another file/path
Cross filesystem?NoYes, if the target is reachable
Can point to directory?Normally noYes
Dangling link possible?No in the same senseYes — target may be removed/moved
InodeSame inode as the originalDifferent inode for the link itself

Create and inspect links

echo "hello" > original.txt
ln original.txt hard.txt
ln -s original.txt soft.txt

ls -li original.txt hard.txt soft.txt
readlink soft.txt
readlink -f soft.txt
stat original.txt hard.txt soft.txt

A hard link is another name for the same underlying file/inode. Removing the original filename does not remove the file while another hard link still exists. A symbolic link stores a path; if that path no longer resolves, the symlink becomes dangling.

Important operational points

  • Hard links cannot cross filesystem boundaries.
  • Use symbolic links when you need a path alias, including links to directories.
  • Prefer relative symlinks when they should remain valid after moving the containing directory tree.
  • Be careful when deleting or replacing symlink targets in production; verify what the link actually points to.

Real-world use: archive old logs

#!/bin/bash
LOG_DIR="/path/to/logs"
ARCHIVE_DIR="/path/to/archive"
DAYS=5

mkdir -p "$ARCHIVE_DIR"

# Find log files older than $DAYS days
OLD_LOGS=$(find "$LOG_DIR" -type f -name "*.log" -mtime +$DAYS)

# Archive them into a timestamped tar.gz, then remove the originals
TIMESTAMP=$(date +'%Y%m%d_%H%M%S')
tar -czf "$ARCHIVE_DIR/logs_archive_$TIMESTAMP.tar.gz" $OLD_LOGS
find "$LOG_DIR" -type f -name "*.log" -mtime +$DAYS -exec rm {} \;

Special variables

VariableMeaning
$0Name of the script or command being run
$1First argument passed to the script
$2, $3, …Second, third, etc. arguments
$#Number of arguments passed
$@All arguments as separate strings (preserves quoting)
$*All arguments as a single string
$$Process ID (PID) of the current script
$?Exit status of the last command (0 = success)
$_Last argument of the previous command
$!PID of the last background process

These are what let a script branch on success/failure ($?) or negate a check with ! — see the process-restart script in Processes — and are the building blocks behind the automation in Monitoring and performance and Archives and compression.
